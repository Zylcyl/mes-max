# MES-MAX · 面向 CNC 数控加工行业的制造执行系统

> 一个从零自建的、面向 **CNC 数控加工 / 精密机加车间** 的 MES（Manufacturing Execution System）。
> 前端为**自研工业化界面（HMI/SCADA 风格）**，不使用任何通用后台模板与通用 AI 界面组件库。
>
> 注意:此项目为个人学习项目，未经过实际落地验证，仅供参考，有兴趣可以给个star~谢谢

---

## 一、项目定位

面向中小型**数控加工企业**（CNC 车削 / 铣削 / 加工中心 / 磨削 / 线切割 / 电火花）的车间级生产执行系统，
解决以下现场问题：

| 现场问题 | MES-MAX 的解决方式 |
|---|---|
| 工单靠纸质流转，进度不可见 | 生产订单 → 工序任务 → 派工单全流程电子化，状态实时闭环 |
| 机台在干什么、干多久没人知道 | 设备联网采集 + 状态机（运行/待机/停机/报警/离线）+ 实时看板 |
| 排产靠班组长脑袋 | 有限产能排产（机台负荷 + 交期 + 优先级）与甘特图排产 |
| 报工靠下班补填工票，工时不准 | 车间触屏报工终端，开工/报工/完工即时落库，自动算 OEE |
| 刀具寿命失控，崩刃撞机才发现 | 刀具台账 + 累计寿命预警 + 刃磨/对刀记录 |
| 首件不做，批量报废 | 首件检验 + 巡检 + 不合格品闭环（返工/返修/让步/报废） |
| 客户要追溯，查不出哪台机哪把刀 | 序列号/批次级正反向全程谱系追溯 |
| 设备点检保养靠纸表 | 点检项目、保养计划、故障台账、MTTR/MTBF |

## 二、技术栈

| 层次 | 技术选型 |
|---|---|
| 后端框架 | Spring Boot 3.2 · JDK 17 |
| 持久层 | MyBatis-Plus 3.5 |
| 数据库 | H2（内置，开箱即跑） / MySQL 8（生产） |
| 鉴权 | 自研无依赖 JWT（HMAC-SHA256）+ 拦截器权限校验 |
| 实时推送 | SSE（Server-Sent Events）实时看板与设备数据流 |
| 前端框架 | Vue 3 + Vite 5 + Pinia + Vue Router |
| 图表 | ECharts 5（仪表盘 / 趋势 / 甘特 / SPC） |
| UI 体系 | **自研工业化设计系统 `ind-*`**（深色钢材 + 青色高亮 + 等宽数字 + 斜切角面板） |

> 前端**不引入 Element Plus / Ant Design / Arco 等通用组件库**，全部为自研的工业控件，
> 视觉语言对标车间 HMI / SCADA / 安灯看板，而非互联网后台。

## 四、快速启动

### 1. 后端（默认 H2，零依赖，开箱即跑）

```bash
cd backend
mvn spring-boot:run
```

启动后：

- 接口地址：`http://localhost:8080/api`
- H2 控制台：`http://localhost:8080/api/h2-console`（JDBC URL `jdbc:h2:file:./data/mesmax;MODE=MySQL;DATABASE_TO_LOWER=TRUE`，用户 `sa`，密码 `mesmax`）
  > 控制台仅在 `h2` profile 下自动装配、且只允许本机访问；生产请用 `mysql` profile（不会开启控制台）。
- 首次启动自动建表 + 灌入 CNC 车间种子数据

若改用 MySQL：

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=mysql
```

### 2. 前端

```bash
cd frontend
npm install
npm run dev
```

浏览器打开 `http://localhost:5173`。

### 3. 默认账号

| 账号 | 密码 | 角色 | 典型使用场景 |
|---|---|---|---|
| `admin` | `mes123456` | 系统管理员 | 全部功能 |
| `planner` | `mes123456` | 计划员 | 订单、排产、派工 |
| `operator` | `mes123456` | 操作工 | 车间报工终端 |
| `quality` | `mes123456` | 质检员 | 检验、不合格品 |
| `keeper` | `mes123456` | 刀具库管 | 刀具台账、刃磨 |
| `device` | `mes123456` | 设备工程师 | 点检、保养、故障 |
| `board` | `mes123456` | 看板浏览 | 只读大屏 |

> 口令在库中以 **BCrypt 哈希**存储（`sql/seed-data.sql` 里写的就是哈希，全链路无明文），
> 任何接口都不会回吐口令字段。历史库若还留着明文，会在该账号首次登录成功时自动升级为哈希，
> 升级前启动日志里会有一条明文口令告警。
>
> 登录失败按账号节流（默认窗口 300 秒内失败 8 次即临时锁定），并可在
> `application.yml` / 环境变量里调整（`MES_DEFAULT_PASSWORD`、`MES_LOGIN_MAX_FAILURES`、`MES_LOGIN_FAILURE_WINDOW`）。


## 八、发现问题，就改问题

**这个仓库欢迎所有人提出问题、动手改问题。** 你不必是 CNC 行业的人，也不必先把整个仓库读完。

- **发现任何问题 → 开 [Issue](https://github.com/Zylcyl/mes-max/issues/new/choose)。**
  跑不通、算不对、看不懂，都算问题。**看不懂本身就是问题**（说明文档没写清）。
  提 Issue 不需要你会写代码，只描述现象也完全可以。
- **想动手改 → 直接提 [Pull Request](https://github.com/Zylcyl/mes-max/pulls)。**
  分支命名、自检清单、代码约定见 [贡献指南](CONTRIBUTING.md)。
  错别字和文档修正不用先开 Issue，直接 PR 更快；动数据库结构或接口契约请先开 Issue 对齐方向。
- **不会因为「改得小」而轻视任何贡献** —— 一行文档修正和一次架构重构同样有价值。

> 项目里每一轮修复都留了**可复跑的回归脚本**（见 [`tools/`](tools/README.md)）。
> 希望你修完问题时，也补一条能复现它的断言，把这个习惯保持下去。
