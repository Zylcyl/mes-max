# 五、接口文档

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 基础路径 | `http://<host>:8080/api` |
| 数据格式 | `application/json; charset=UTF-8` |
| 鉴权 | 请求头 `Authorization: Bearer <token>`；也支持 `X-Token` 头；**仅 SSE（`/board/stream`）**支持查询参数 `?token=` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（查询参数中的 LocalDateTime 使用 ISO 形式 `2026-09-21T08:00:00`） |
| 分页参数 | `page`（从 1 开始）、`size` |
| 分页边界 | `page` 最小 1，`size` 上限 **500**；越界值会被夹取而不是报错 |
| 过滤参数 | 直接传字段名（如 `status=RUN`）；区间用 `<字段>Start` / `<字段>End`；模糊用 `keyword` |
| 排序参数 | `sort=createTime&order=desc` |
| 接口总数 | 227 条路由（28 个控制器，含 `BaseCrudController` 为 18 个子类提供的 7 个通用 CRUD 端点） |

### 1.1 统一响应结构

```json
{
  "code": 200,
  "msg": "success",
  "data": { },
  "ts": 1789991234567
}
```

分页数据：

```json
{ "code": 200, "msg": "success",
  "data": { "total": 34, "page": 1, "size": 20, "records": [ ] } }
```

### 1.2 业务码

| code | 含义 | 前端行为 |
|---|---|---|
| 200 | 成功 | 正常渲染 |
| 400 | 参数错误 / 业务规则拒绝（数量为负、状态不允许…） | Toast 提示 |
| 401 | 未登录 / 令牌失效 | 清空令牌并跳转登录页 |
| 403 | 当前账号无该功能权限 | Toast 提示 |
| 404 | 记录不存在 | Toast 提示 |
| 405 | 方法不支持 | Toast 提示 |
| 409 | 状态冲突（例如对已完工的派工单再次开工/报工） | Toast 提示 |
| 429 | 登录失败次数过多，账号被临时锁定 | Toast 提示 |
| 500 | **服务端异常**（响应只给追踪号，细节进服务端日志） | Toast 提示 |

> **HTTP 状态码与业务码一致**：以上 `4xx` 业务码都会以相同的 HTTP 状态码返回，
> 网关、Nginx、监控与前端 fetch 拿到的是同一个判断依据（而不是「HTTP 200 + 体里写 401」）。
> 权限判定基于**已 URL 解码**的查找路径（`%73ystem` 这类编码写法不能绕过）。
> 角色权限查不到时按「拒绝」处理，不会默认放行。
>
> **读接口的权限边界**：现场数据（看板、机台、订单、质量、追溯、报表）对所有登录账号开放；
> 但 `/system/user/**`、`/system/role/**`、`/system/log/**` 的读取同样需要 `system` 权限 ——
> 否则只读角色能拉到全厂账号的手机号与别人的操作参数。字典读取（`/system/dict/**`）
> 保持对所有登录账号开放，因为前端启动时各角色都要拉它。
>
> **口令**：库中以 BCrypt 哈希存储；所有接口（登录、用户列表、用户保存）
> 都不会在响应里返回口令字段。种子数据写入的**本身就是哈希**（全链路无明文）；
> 历史库中的明文会在该账号首次登录成功时自动升级为哈希。
>
> **登录节流**：同一账号在 300 秒窗口内失败 8 次后返回 `429`（阈值见 `mes-max.security.*` 配置）。

## 2. 认证与系统管理

### `/auth` — 认证

| 方法 | 路径 | 说明 |
|---|---|---|

`dashboard` `order` `schedule` `dispatch` `report` `terminal` `respond` `quality` `spc` `tool`
`equipment` `fault` `maint` `trace` `stats` `masterdata` `system`

> 读接口（GET/OPTIONS）对所有登录账号开放；写接口按路径前缀匹配模块权限。
> `dashboard`（车间看板与设备监控）默认授予全部业务角色 —— 看板是车间公共信息。

| GET | `/stats/output?days=14` | 产量、合格率、交期达成率、完成率 |
| GET | `/stats/labor?days=7` | 人员工时、产出、合格率、小时产出、班次工时 |
| GET | `/stats/summary?days=7` | 报表首页聚合（一次拿全） |

> **OEE 口径唯一**：`/machine/{id}/oee` 与 `/stats/oee` 共用 `OeeService`，同一台机的四个指标完全一致。
> 理论节拍取工艺定额（`Σ 单件工时 × 报工数量`）；当区间内取不到定额时，
> `performance` 与 `oee` 返回 `null`（前端显示 `—`），并给出 `theorySource: "missing"`，
> 而不是返回一个编造的百分比。
>
> **订单产出语义**：`/stats/output` 的 `finishedQty` 来自各订单**最后一道工序**的完工数（成品数），
> 因此完成率不会因为「前面的工序做得多」而虚高。

## 6. 制造主数据（9 个资源，均为标准 CRUD）

`/md/workshop` 车间 · `/md/workCenter` 工作中心 · `/md/machine` 机床 · `/md/material` 物料 ·
`/md/bom` BOM（含 `/md/bom/items/{bomId}`）· `/md/process` 工序 ·
`/md/routing` 工艺路线（含 `/md/routing/steps/{routingId}`）· `/md/customer` 客户 ·
`/md/employee` 员工 · `/md/shift` 班次

每个资源都提供以下 7 个接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/md/<资源>/page` | 分页查询 |
| GET | `/md/<资源>/list` | 不分页查询 |
| GET | `/md/<资源>/{id}` | 单条查询 |
| POST | `/md/<资源>/save` | 保存（带 id 为更新，不带为新增） |
| PUT | `/md/<资源>/update` | 更新 |
| DELETE | `/md/<资源>/delete/{id}` | 删除 |
| POST | `/md/<资源>/delete/batch` | 批量删除（body 为 id 数组） |

> 主数据写操作需要 `masterdata` 权限（默认仅管理员）。
