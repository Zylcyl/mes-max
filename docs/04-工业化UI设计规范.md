# 四、工业化 UI 设计规范

> 设计目标：**让界面看起来像车间里的设备面板，而不是又一个互联网后台。**
>
> 本系统前端不引入任何通用组件库（Element Plus / Ant Design / Arco 等），
> 全部控件在 `src/components/ind/` 下自研，样式由 `src/design/` 下的三个文件统一约束。

## 1. 为什么通用后台界面不适合车间

| 维度 | 通用后台（如 Element Plus 默认） | 车间 HMI / 本系统 |
|---|---|---|
| 底色 | 白色 / 浅灰，明亮 | 深色冷灰钢蓝（`#0a0e13` ~ `#182230`），长时间盯屏不刺眼 |
| 圆角 | 6~8px 大圆角 | 2~3px 近乎直角（工业设备面板没有大圆角） |
| 行高 | 宽松（40~48px） | 紧凑（30~32px），一屏能看更多机台 |
| 状态表达 | 彩色标签为主 | **LED 指示灯 + 呼吸/闪烁动画 + 状态色边框**，远距离可辨 |
| 数字 | 普通字体 | 等宽数字字体（Bahnschrift / DIN），数字对齐便于比对 |
| 信息密度 | 舒适优先 | 密度优先：一屏内呈现 12 台机台的实时状态 |
| 装饰 | 阴影、渐变、插画 | 网格底纹、角标折线、斜切角、扫描线，模拟仪表与图纸 |
| 使用场景 | 办公桌 1 米内 | 车间挂墙大屏 5~10 米外 + 触屏一体机戴手套操作 |

| `--bg-hover` / `--bg-active` | `#1d2937` / `#22303f` | 悬停 / 选中 |

### 2.2 线条

### 2.3 状态色（**全站语义唯一来源**）

| 状态 | 令牌 | 色值 | 语义 |
|---|---|---|---|
| 运行 | `--c-run` | `#1fc96b` | 机台正在加工、检验合格、产量达成 |
| 待机 | `--c-idle` | `#f5a524` | 待料/待派工、寿命预警、需要关注 |
| 停机 | `--c-stop` | `#ff4d4f` | 停机、不合格、超差 |
| 报警 | `--c-alarm` | `#ff2d55` | 设备报警、安灯待响应（闪烁） |
| 离线 | `--c-offline` | `#657586` | 通讯中断、未分配 |
| 保养 | `--c-maint` | `#a855f7` | 保养中、检验中 |
| 主色 | `--c-primary` | `#0aa2ff` | 主要动作、选中态、进度 |
| 青色 | `--c-cyan` | `#16d3d3` | 实时数据、程序号、次要强调 |

配套 `--c-run-bg` 等半透明底色令牌，保证「色块底 + 同色文字 + 同色边框」三件套一致。

### 2.4 字体

```css
--font-ui:      'Microsoft YaHei', 'PingFang SC', 'Segoe UI', Arial, sans-serif;
--font-display: 'Bahnschrift', 'DIN Alternate', 'Oswald', 'Microsoft YaHei', sans-serif;  /* 标题/大数字 */
--font-num:     'Bahnschrift', 'DIN Alternate', 'JetBrains Mono', 'Consolas', monospace;  /* 所有数字 */
```

- **全部使用系统字体**，不加载任何 Web Font —— 车间内网常常无外网，字体缺失会直接毁掉界面。
- 数字统一 `font-variant-numeric: tabular-nums`，保证竖向对齐便于横向比对。
- 大屏时钟、KPI 数字、程序号、坐标值一律走 `--font-num`。

### 2.5 尺寸

| 令牌 | 值 | 说明 |
|---|---|---|
| `--radius` / `--radius-lg` | 2px / 3px | 近乎直角 |
| `--h-topbar` / `--h-nav` | 50px / 42px | 顶栏 / 导航项高度 |
| `--row-h` | 32px | 表格行高（紧凑 26px） |
| `--sp-1 … --sp-8` | 4 / 8 / 12 / 16 / 20 / 24 / 32px | 间距阶梯 |

## 4. 大屏（BoardLayout）与控制台（ConsoleLayout）分离

这是本系统在信息设计上最重要的一条决定：**挂在墙上的看板和办公电脑上的界面是两种产品。**

| 维度 | 大屏 `/board` | 控制台（其余页面） |
|---|---|---|
| 导航 | 无侧边栏（避免误点） | 左侧 6 组导航 + 折叠 |
| 顶栏 | 58px 品牌 + 大时钟（22px）+ 数据通道 LED | 50px 品牌 + 页面标题 + 时钟 + 班次 + 安灯计数 + 用户 |
| 字号 | 整体放大，KPI 数字 26px+ | 常规 12~13px |
| 背景 | 径向渐变 + 网格底纹 | 常规面板 |
| 刷新 | SSE 每 2 秒自动刷新 | 按需刷新 + 关键页 15~30 秒轮询 |
| 布局 | 三栏网格：机台矩阵（占两行） + OEE + 产量 + 安灯 + 停机 TOP | 面板纵向堆叠 |

## 5. 信息设计规范

### 5.1 机台卡（车间看板最小信息单元）

一眼必须回答三个问题：**这台机在干什么、干得顺不顺、做了多少。**

```
┌──────────────────────────────────────┐
│ ● MC-001   运行        32m           │  ← 状态灯 + 机台号 + 状态 + 已持续时长
│ 立式加工中心1号  立式加工中心           │  ← 机台名与设备类型
│ 程序 O1050_VMC_NC              H01   │  ← 当前程序号 + 刀补号
│ S ▓▓▓▓▓▓▓░░░       6,200            │  ← 主轴转速（条 + 等宽数字）
│ L ▓▓▓▓░░░░░░          52%           │  ← 主轴负载（超 85% 变红）
│ WO…213455 精铣              12/62    │  ← 工单号 + 工序 + 已加工/计划
└──────────────────────────────────────┘
```

状态色同时作用于**左侧 3px 边框 + 状态文字 + LED**，三处冗余表达，
保证 5 米外也能判断运行/停机/报警。

### 5.2 数字表达

| 场景 | 规范 | 示例 |
|---|---|---|
| 数量 | 千分位 + 等宽 | `3,087` |
| 百分比 | 一位小数 + `%` | `57.4%` |
| 时长 | `2h35m` / `45m`（不写「2小时35分钟」，省宽度） | `12h08m` |
| 时间 | 列表用 `MM-DD HH:mm`，详情用完整时间 | `09-21 14:32` |
| 坐标 | 三位小数 | `320.118` |
| 空值 | 统一 `—`（不用 `null` / `N/A`） | `—` |

### 5.3 图表规范（`src/utils/chart.js`）

- 统一深色主题：透明背景、`#223040` 细网格（虚线、55% 透明）、11px 轴标签。
- 启用 `tabular-nums`，提示框深色半透明 + 主色指示线。
- 语义固定：产量=主色蓝、不良/停机=红、合格/运行=绿、待机/预警=黄、保养/刃磨=紫。
- 常用构造器：`lineOption` / `barOption` / `paretoOption`（帕累托）/ `gaugeOption`（仪表）/
  `ringOption`（环形）/ `spcOption`（控制图，控制限虚线、规格限实线，符合质量工程师看图习惯）。

### 5.4 动效规范

| 动效 | 用途 | 参数 |
|---|---|---|
| LED 呼吸 | 运行中 | 2.4s 循环，透明度 1 → 0.45 |
| LED 高频闪烁 | 报警 / 待响应安灯 | 0.7s `steps(2,start)` |
| 机台卡报警脉冲 | 报警机台整体边框呼吸 | 1.6s 内阴影渐变 |
| 数据进度条 | 进度变化 | 0.4s ease |
| 过渡 | 面板/弹层 | 0.12~0.18s，无弹跳缓动 |

**克制原则**：动效只用于表达「状态正在变化」或「需要立刻关注」，
不做装饰性动画 —— 车间里 12 台机同时闪烁会让人无法聚焦。

## 6. 触屏终端规范（`/terminal`）

| 规范 | 取值 | 理由 |
|---|---|---|
| 主操作按钮 | 56px 高（`IndButton --xl`），17px 字号，字距 0.1em | 戴手套可点，1 米外可读 |
| 按钮数量 | 一屏最多 4 个主操作：开工 / 报工 / 完工 / 停机 | 减少选择 |
| 机台切换 | 顶部横向 chip 列表，带状态色下边框 | 换机床只需一次点击 |

## 7. 落地检查表

新增页面时逐条自查：

- [ ] 只用设计令牌（`var(--xxx)`），不写裸色值、不写魔法间距
- [ ] 状态一律通过 `utils/status.js` 取中文名与色调，不散落硬编码
- [ ] 数字用 `.mono` + `num()`/`pct()`/`minutes()` 格式化，空值为 `—`
- [ ] 列表用 `IndTable` + `IndPager`，容器用 `IndPanel`
- [ ] 统计页面顶部先给 KPI，再给趋势图，最后给明细表（先结论后细节）
- [ ] 大屏类页面不放进控制台布局，使用 `meta.full` 走 `BoardLayout`
- [ ] 不引入任何外部字体、图标库或 CDN 资源

## 8. 主题：深色（车间默认）与浅色（白色背景）

### 8.1 为什么要两种主题

| 主题 | 使用场景 | 说明 |
|---|---|---|
| **深色**（默认） | 车间挂墙大屏、中夜班值守、机台旁触屏 | 长时间盯屏不刺眼，与设备面板/HMI 的既有观感一致 |
| **浅色** | 办公室电脑、投影与答辩演示、白天强光环境 | 白底深字，投影和打印预览下更清楚 |

切换按钮的位置：

- **车间看板（大屏）**：顶栏右侧，与「进入控制台」并列；
- **控制台**：顶栏右侧、用户信息左侧（图标 + 「浅色 / 深色」文字）。

选择结果记在 `localStorage.mesmax_theme`，并在**应用挂载之前**写入 `<html data-theme>`，
因此刷新不会出现「先黑一下再变白」的闪烁。

### 8.2 实现方式：令牌覆盖，而不是维护两套样式

主题只做一件事 —— 在 `:root[data-theme='light']` 里重新赋值整套设计令牌：

```css
:root { --bg-panel: #131b24; --text: #dbe6f0; /* …深色，默认 */ }
:root[data-theme='light'] { --bg-panel: #ffffff; --text: #22303c; /* …浅色 */ }
```

组件样式**只引用 `var(--x)`**，因此不需要知道自己跑在哪个主题下。
浅色并不是「通用后台的纯白」，而是**冷灰白工业配色**：底色 `#eef2f6`、面板纯白、
线条蓝灰 `#cfd9e3`、正文 `#22303c`；状态色（运行绿 / 待机黄 / 停机红 / 报警红 / 保养紫）
保留同一语义色相，只把亮度压深以保证白底上的对比度（运行绿 `#1fc96b → #128a4c`）。
弱化文字也从 `#7d8d9c` 压到 `#63758a`（白底对比度约 3.1:1 → 4.8:1）。

### 8.3 图表的特殊处理（唯一的例外）

ECharts 画在 `<canvas>` 上，**用不了 CSS 变量**（`var(--x)` 会被当普通字符串丢掉），
所以图表颜色只能在 JS 里给具体值。主题切换时由 `src/utils/chart.js` 的 `swapColorsForTheme()` 处理：

- 只替换**中性色**：网格 `#223040 → #cfd9e3`、轴标签 `#8b9db0 → #55677a`、
  正文 `#dbe6f0 → #22303c`、tooltip 底 `rgba(11,17,24,.96) → rgba(255,255,255,.97)`；
- **状态色保持不变** —— 语义色不该随主题变，白底上依然可辨识；
- 深度遍历数组/嵌套对象，且**不就地修改原 option**（否则会污染组件的 `computed` 缓存）。

这段逻辑错了的表现是「轴标签看不见 / 网格糊成一片」，而页面并不会报错，所以配了独立断言：

```bash
node tools/check-chart-theme.mjs      # 9 项断言
```

### 8.4 新增样式时的硬性要求

```bash
# 组件里出现写死的十六进制颜色就说明有问题（只允许出现在 tokens.css）
rg -n "#[0-9a-fA-F]{6}" frontend/src --glob "!**/tokens.css"
```

写死颜色的代价是**它不会跟着主题变**：深色下看着正常的 `#0f151c` 底色，
配上浅色主题的深色文字就变成「深字压深底」完全不可读。`工票预览` 就踩过这个坑，现已改为 `var(--bg-well)`。
