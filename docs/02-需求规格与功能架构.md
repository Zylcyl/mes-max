# 二、需求规格与功能架构

## 1. 业务背景：数控加工车间的真实痛点

一家典型的中小型数控加工企业（20~60 台机床、单件小批多品种）通常长这样：

| 现状 | 后果 |
|---|---|
| 工单靠纸质流转，插单靠吼 | 计划员不知道每台机在干什么，交期靠拍脑袋 |
| 机台状态靠人巡 | 停机半小时没人发现，OEE 无人统计 |
| 报工靠下班补填工票 | 工时不准 → 成本算不准 → 报价越来越离谱 |
| 刀具寿命靠操作工感觉 | 崩刃撞机才发现，一批工件全废 |
| 首件检验时有时无 | 程序或刀补错了，直接批量报废 |
| 客户要追溯只翻得出工单号 | 出了质量问题无法界定召回范围 |

**MES-MAX 的目标**：把「工单 — 机台 — 人 — 程序 — 刀具 — 毛坯 — 质量」这七个对象用数据串起来，
让车间从「凭经验」变成「看数据」。

## 2. 用户角色与使用场景

| 角色 | 所在页面 | 典型动作 | 使用频率 |
|---|---|---|---|
| 车间主任 / 班组长 | 车间看板（大屏）、安灯呼叫 | 看机台状态矩阵、处理安灯、盯 OEE | 每小时多次 |
| 生产计划员 | 生产订单、生产排产、派工管理 | 下达工单、自动排产、插单调整、生成派工 | 每天 1~3 次排产 |
| 机床操作工 | 车间报工终端（触屏） | 开工、报工、完工、报停机、呼叫安灯 | 每件/每批都操作 |
| 质量检验员 | 质量检验、SPC 过程控制、谱系追溯 | 首件/巡检/终检、录入实测值、判定、处置不合格品 | 每批多次 |
| 刀具库管员 | 刀具管理 | 装刀、卸刀、刃磨登记、对刀、寿命预警处理 | 每天多次 |
| 设备工程师 | 设备维保、设备监控 | 班前点检、保养执行、故障响应与关闭 | 每天多次 |
| 工艺工程师 | 设施主数据（工艺路线） | 维护工序、定额工时、NC 程序号与刀具要求 | 按需 |

## 4. 功能清单

### 4.1 车间监控域

| 功能 | 说明 | 关键设计 |
|---|---|---|
| 车间实时看板 | 机台状态矩阵、8 项 KPI、OEE 仪表、小时节拍、安灯与报警、停机 TOP | SSE 每 2 秒推送，无刷新 |
| 设备监控 | 单机深度监视：实时工况 8 项参数、实时趋势（2 秒）+ 历史趋势（30 秒落库）、在制派工、在机刀具、状态履历、故障履历、单机 OEE | 内存实时态 + 时序库双通道 |
| 安灯呼叫 | 呼叫看板、响应/升级/关闭、按类型/等级/机台统计、平均响应与关闭时长 | 三级升级：班组 → 车间 → 厂部 |

### 4.2 生产执行域

| 功能 | 说明 | 关键设计 |
|---|---|---|
| 生产订单 | 工单 CRUD、下达、展开工序、齐套检查、挂起/恢复、执行跟踪 | 下达时**快照**定额工时与 NC 程序号 |
| 生产排产 | 有限产能自动排产、甘特图、机台负荷、待排任务池、手工指派 | JobShop：加权优先级 + 最早空闲机台 |
| 派工管理 | 生成派工单、批量派工、接单、工票打印 | 一张工票可下车间（含程序号与刀具要求） |
| 车间报工终端 | 触屏大按钮：开工（含程序号校验）、报工、完工、停机登记、安灯呼叫、机台状态切换 | 以机台为第一视角，全部录入 ≤3 次点击 |
| 停机分析 | 停机明细、原因帕累托、按日趋势、按机台排名、计划/非计划构成 | 停机原因字典化，是 OEE 改进的入口 |

### 4.3 质量与工艺域

| 功能 | 说明 | 关键设计 |
|---|---|---|
| 质量检验 | 首件/巡检/终检，检验项明细与自动判定，检验合格率统计 | 关键工序首件未判定合格不允许批量加工 |
| 不合格品处置 | 缺陷登记、责任原因、四态处置、质量损失统计 | 返工/返修/**让步接收**/报废 四态闭环 |
| SPC 过程控制 | I-MR 控制图、移动极差图、Cp/CpK、超控/超差判定与改善建议 | σ 由移动极差估计（σ = MR̄/1.128） |
| 刀具管理 | 台账、装刀/卸刀、寿命累计与预警、刃磨复位、对刀测量、反向追溯 | 寿命 ≥85% 预警、≥100% 禁止装刀 |

### 4.4 设备维保域

| 功能 | 说明 | 关键设计 |
|---|---|---|
| 班前点检 | 按机台类型自动带出点检项，逐项「正常/异常」，异常转设备处理 | 关键项异常率纳入统计 |
| 保养计划与工单 | 保养计划、一键生成工单、完成后自动推算下次保养日期 | 支持月/季/年周期 |
| 故障台账 | 故障登记、响应、修复关闭、备件记录，自动生成停机记录 | MTTR / MTBF 自动计算 |

### 4.5 追溯与报表域

| 功能 | 说明 | 关键设计 |
|---|---|---|
| 谱系追溯 | 正向（序列号 → 全过程）、反向（批次/刀具/机床/程序 → 受影响工件）、毛坯批次台账 | 两个方向都要能查，这是行业合规底线 |
| 统计报表 | OEE（整体/机台/工作中心/按日）、产量与交期达成、人员工时与产出 | 三级 OEE 分解，可直接定位瓶颈 |

### 4.6 系统管理域

| 功能 | 说明 |
|---|---|
| 用户与角色 | 账号、角色、功能权限（按模块前缀校验）、重置密码 |
| 数据字典 | 状态、停机原因、缺陷类型、处置方式等枚举的颜色与排序统一管理 |
| 系统日志 | 登录日志 + 操作日志（所有写操作留痕：模块、接口、耗时、结果） |
| 制造主数据 | 物料、机床、工序、工艺路线、客户、员工、班次、车间、工作中心的维护 |

## 5. 关键业务流程

### 5.1 主流程：从订单到完工

```
计划员                    系统                        操作工（触屏终端）           质检员
  │                        │                              │                        │
  ├─ 新建工单 ──────────▶ 生成工单号、带出工艺路线         │                        │
  ├─ 齐套检查 ──────────▶ 按 BOM 折算毛坯/标准件需求       │                        │
  ├─ 下达工单 ──────────▶ 展开工序任务（快照定额与程序号）  │                        │
  ├─ 一键自动排产 ──────▶ 加权优先级 + 最早空闲机台        │                        │
  ├─ 派工 ─────────────▶ 生成派工单 + 可打印工票 ─────────▶│                        │
  │                        │                              ├─ 开工（校验程序号）     │
  │                        │                              ├─ 报工（数量/不良/刀具）  │
  │                        │◀─ 数量三级联动：报工→工序→订单  │                        │
  │                        │                              ├─ 完工 ────────────────▶├─ 首件/终检
  │                        │                              │                        ├─ 录入实测值并判定
  │                        │◀────────────────── 检验留痕（可追溯）──────────────────┤
  完工 → 订单状态自动置 FINISHED，OEE / 产量 / 合格率实时更新
```

### 5.2 异常流程

| 场景 | 系统行为 |
|---|---|
| 开工时程序号与工艺不符 | **拒绝开工**并提示工艺要求的程序号（防止程序错版批量报废） |
| 关键工序首件不合格 | 检验单判定为 FAIL，工序停留在「检验中」，不进入批量加工 |
| 刀具寿命 ≥100% | 装刀被拒绝，提示必须先刃磨或更换 |
| 机台故障 | 登记故障 → 响应 → 修复关闭，自动生成停机记录（OEE 时间损失口径一致） |
| 现场异常 | 呼叫安灯（三级升级），响应与关闭时长进入安灯效率统计 |
| 物料不齐套 | 齐套检查给出缺料缺口，排产前即可发现 |

## 6. 非功能需求

| 项 | 指标 | 实现方式 |
|---|---|---|
| 实时性 | 看板数据延迟 ≤2 秒 | SSE 推送 + 内存实时态，避免每 2 秒查库 |
| 开箱可用 | 一条命令启动，无需额外安装数据库 | 内置 H2 文件库 + 自动建表 + 自动灌种子 |
| 可移植 | 换 MySQL 只改 profile，不改代码 | `--spring.profiles.active=mysql`，同一份 DDL |
| 离线部署 | 不依赖外网 CDN / 字体 / 图标库 | 前端零外部资源，图标为内联 SVG，字体用系统字体栈 |
| 操作安全 | 写操作全部留痕 | 拦截器记录模块、接口、耗时、结果 |
| 权限 | 读接口对所有登录账号开放，写接口按模块校验 | 角色 perms 白名单 + 路径前缀匹配 |
| 可维护 | 无 IDE 文件、无本地 jar、依赖全部走 Maven/npm 坐标 | 见 .gitignore 与 pom.xml |
